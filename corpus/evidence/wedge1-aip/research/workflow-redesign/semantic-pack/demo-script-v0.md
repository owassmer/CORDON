# Demo script v0

Status: APPROVED v0, amended 2026-08-24 — INDETERMINATE/refusal remain product behaviors, not hero/demo thesis; v1 adds timings and exact bound events after rehearsal
Class: O0 build-planning artifact. It defines which trajectories must run end-to-end and therefore what gets populated. It does not define the product; the operator surface stays demo-agnostic.
Timings: none until rehearsal. v1 adds second budgets after the trajectories run.

## Frame

Recorded on the Workshop Decision Loop, structured as the six-question grammar. Every fact shown on the operator surface presents as the real operating picture (Owen ruling D5). Data provenance is presented by Owen separately from the recording, never as an on-surface disclosure state.

## Beats

1. **Cold open.** The problem in one breath: a cooperative operations manager coordinates dozens of member cases across compulsory duties and funded recovery; authority is split across many actors; rules change mid-year; deadlines carry legal effect silently. A manager's day is six questions. This system gives each question an owner, a basis, and an audit trail.
2. **Q1 — what changed.** A material change arrives (binding E1). `Determine Affected Decisions` returns affected work AND explicitly unaffected work. Map lens shows where. One click on a fact shows its source basis and as-of.
3. **Q2/Q4 — required and ready.** Briefly show named-action readiness on `Dispatch Intervention`: the relevant premise, cure owner and current readiness. Refusal and INDETERMINATE behavior are exercised in Evals and available in the product; they are not a dedicated demo beat.
4. **Q3 — one bounded feature.** Where capacity is genuinely scarce, compare a small set of feasible alternatives and let the manager commit the selected plan with the exact capacity Action and a durable receipt. Use the simplest native mechanism that preserves complete-set validation and atomicity; capacity is not the product thesis.
5. **Q5/Q6 — done and landed.** An external outcome (binding E4) arrives through the authenticated legal/public ingestion path. `Determine Remaining Exposure` shows independent legal, operational, financial, and biological lines; an order is not cash. Replay the same envelope: one occurrence, no duplicate.
6. **Under the hood.** 11 visible fact owners + hidden occurrence substrate; four kernels shared between explanation and Action revalidation; exact 7 FK / 19 M:M / 8 object-backed link map; chatbot allowlist of six reads and four writes; Evals suite with refusal/INDETERMINATE cases; Data Expectations and Health; Action logs and receipts.
7. **Close.** What is next: consented cooperative data pack; tuned action-execution model behind the same frozen Evals; background autonomy granted Action by Action from evidence.

## Never-cut list

These three are the thesis; everything else is descopable:

1. the persistent Now/five-responsibility + Map + AIP operating picture;
2. one full Action trajectory ending in a durable receipt;
3. one evidence-basis click (source + as-of on a shown fact).

## Descope ladder (invoked in order, only when needed)

1. Automate beat narrated instead of shown.
2. Evals shown as results screenshot instead of live run.
3. Capacity mechanism falls back from Scenarios + staged writes to Proposal + bounded atomic function-backed Action; proposal immutability, complete-set validation, and receipt semantics are preserved; the narration says so.
4. Ingestion beat becomes a pre-loaded outcome with the envelope shown.

## Narrated versus shown

Shown: persistent Now/responsibility rail + Map + AIP panel; affected/unaffected result; concise readiness; Scenario comparison; conversational commit and receipt; exposure lines; replay; evidence click. Narrated: refusal/INDETERMINATE coverage, Automate detection (unless cheap to show), Evals context, model roadmap.
