# Gate 5 kinetic and interface candidates

**Status:** PRE-CORRECTION KINETIC UPPER BOUND — Actions, Functions and Interface reopened
**Date:** 22 August 2026  
**Authority:** `REDESIGN_SEQUENCE.md`; accepted `connected-operating-model.md`; accepted Gate 3–4 inventory; `gate-5-core-ontology.md`; `gate-5-reground.md`; `gate-5-documentation-mece-reconciliation.md`; `gate-5-mece-post-correction-verification.md`; current official Palantir Ontology guidance

## Executive verdict

Deletion-first produced the following kinetic upper bound.

The operator-centered correction reopens this inventory. Retain the authority/refusal analysis, but admit an Action only when the cooperative manager or another real CORDON actor can execute/stage it through the bounded AIP harness. External public decisions CORDON merely receives are outcomes, not Actions.

- **KEEP eleven cohesive Action semantics:** elect voluntary participation; accept the cooperative execution mandate; certify technical Intervention design; release a public application; commit or rebalance Intervention capacity; dispatch an Intervention; attest Intervention performance; decide compulsory compliance acceptance; decide funded-work acceptance; decide contractual acceptance; and release a payment claim.
- **KEEP three Function semantics:** determine the decisions affected by a material change; assess readiness for one named action; and compare feasible scarce-capacity portfolios. These are admitted only because their answers require current traversal or complex cross-object operational logic. They do not imply a language, repository, application, or derived-property choice.
- **KEEP one narrow Interface:** `Decision-Capable Actor`, implemented by Natural Person and Organization. It applies only where the same exact relationship or workflow accepts either concrete actor under an otherwise identical six-dimensional contract. All broader subject, scope, right-holder and route abstractions remain rejected.

External public decisions, authoritative-source corrections, cash settlement, execution occurrences and establishment observations remain consequential facts even when no core Action is admitted for taking them in CORDON. An Action is not required merely to display or ingest an outcome. Likewise, deterministic applicability, eligibility, settlement and reopening rules are not automatically Functions: the semantic calculation is separated below from the eventual implementation mechanism.

## Decision rules applied

### Deletion-first admission

A candidate survives only if deleting it would remove a required operator decision, governed real operation, or live computation from the accepted six-question model. Convenience, form reuse, a familiar platform primitive, or a possible future surface is insufficient.

### Action tests

Current official Palantir guidance defines an Action as a single transaction over cohesive object/property/link edits and side effects, governed independently by submission criteria. Actions should express overall business operations rather than individual property edits. Therefore each retained Action must:

1. name a real operation or reserved decision;
2. be owned by the actor with that decision right;
3. apply one bounded and internally cohesive consequence atomically;
4. refuse when the submitting actor lacks the exact contextual authority or when a mandatory premise for that operation is unresolved; and
5. avoid generic CRUD, status setters, universal `decide`, `approve`, `record event`, or `advance workflow` verbs.

An Action may record the consequence of the operation it governs; that does not make a generic event or status object necessary. A Function that edits the Ontology would remain behind an Action, but no implementation is selected here.

### Function tests

A candidate Function survives only when the operator needs a current answer that requires live traversal across accepted objects/relationships, combinatorial comparison, or similarly complex operational logic that cannot safely be represented as one stored fact, a stable precomputed transformation, a simple Action rule, or direct reading of authoritative outcomes. “Deterministic” does not itself mean “Function.” Deterministic applicability, eligibility, readiness, settlement and reopening are classified separately below.

### Interface tests

An Interface is abstract and non-instantiable and must describe a proven common shape or capability implemented by concrete object types. Shared labels, common participation in a generic link, or a wish for one form are not enough. Current Palantir support is uneven: TypeScript v2 Functions support Interfaces; Actions and Object Set Service support them only partially; language support varies; and Interface Action constraints are Beta, describe shape rather than behavior, and cannot currently be discovered or invoked by end users or OSDK. No candidate below selects or depends on a surface.

### Anti-pattern results

- **Golden Hammer:** calculations do not become Actions; external outcomes do not become manual Actions merely to enter data; event-driven reactions do not become Functions by default; and stable/precomputable determinations remain outside the core Function inventory.
- **Action Sprawl:** no field setter, generic state transition, evidence upload, hold toggle, capacity-state setter, settlement checkbox, or separate action per acceptance field survives.
- **God Object / Misnomer:** no universal `Decide Case`, `Advance Route`, `Record Outcome`, `Workflow Subject`, `Scope Item`, or `Party/Asset/Work` supertype survives. The accepted nouns and distinct authority boundaries remain visible.

## Candidate Actions

Verdicts apply to the **semantic Action contract**, not to a particular rule kind, parameter list, submission-criteria syntax, permission, side effect, Action log, application, or API name.

### A1. Elect voluntary participation — **KEEP — ACCEPTED**

- **Decision owner:** member or beneficiary; an authorized representative may execute only within an operative mandate.
- **Bounded semantic inputs:** the member/beneficiary identity, relevant Holding and proposed voluntary route, the applicable Programme/Measure or self-funded basis, the exact election being made, and any authority instrument for a representative.
- **Atomic effects:** records the member’s affirmative or negative participation election for the named route and updates only the proceeding/scope or actor assignment facts that legally follow from that election. It does not create public eligibility, concession, cooperative capacity, or a creditor right.
- **Output:** the member-owned route election, its operative context, and the route(s) that remain available.
- **Refusal boundary:** refuse if the submitter is not the member/beneficiary or properly authorized representative; the route/election is not identified; the relied-on mandate is absent, expired, contradicted, or out of scope; or the Action would purport to decide public eligibility or cooperative acceptance.
- **Deletion consequence:** the model could calculate opportunity and readiness but could not preserve the member’s separate voluntary decision right; collective pursuit would again risk being inferred from eligibility or management nomination.
- **Anti-pattern result:** one real election, not a `participating=true` setter. Funding-source election remains a separate input only when the governing instrument makes it consequential; this Action must not silently bundle an independent funding-source choice.
- **Executive result:** Owen accepts one member-owned Action across named funded, self-funded, collective and individual voluntary routes. It updates only scoped facts that legally follow and preserves fallback/right boundaries.

### A2. Accept the cooperative execution mandate — **KEEP — ACCEPTED**

- **Decision owner:** cooperative role competent under the cooperative’s governance and the negotiated agreement.
- **Bounded semantic inputs:** member/beneficiary, cooperative Organization, proposed mandate Instrument, affected Intervention or bounded route scope, term, powers, duties, exclusions, and any member-side execution already completed.
- **Atomic effects:** accepts or refuses the negotiated cooperative execution mandate and, when accepted, instantiates only the resulting scoped F1 authority/responsibility relationship. It does not decide member participation, public concession, capacity allocation, or field dispatch.
- **Output:** accepted/refused cooperative mandate consequence, its bounded scope, and the member route that continues individually if collective execution is not accepted and the programme permits it.
- **Refusal boundary:** refuse when the cooperative submitter lacks the exact acceptance authority; the member election or operative mandate proposal is absent; terms/scope conflict materially; or acceptance would transfer member-specific creditor identity without an operative basis.
- **Deletion consequence:** public eligibility and member adhesion would again be liable to masquerade as cooperative execution authority, violating an explicit accepted separation.
- **Anti-pattern result:** cohesive governance decision, not a generic link creator or mandate-status setter.
- **Executive result:** Owen accepts one cooperative-owned Action that requires a real member-granted mandate Instrument. CORDON does not create the member's grant. A separate Grant Action requires later direct evidence that CORDON is the authoritative signing channel.

### A3. Certify technical Intervention design — **KEEP — ACCEPTED**

- **Decision owner:** technician or technical Organization holding exact professional design responsibility; any separate public permit remains owned by the competent authority.
- **Bounded semantic inputs:** one Intervention, intended Parcel/Plant scope, Cultivar/material design, technical assumptions, applicable Instrument/Proceeding constraints, named professional assertion, and technician assignment.
- **Atomic effects:** establishes the professionally certified Intervention physical/material scope and the technician’s bounded assertion/responsibility. It neither grants a permit nor accepts execution, reserves capacity, commits a contractor, or dispatches work.
- **Output:** professionally certified design scope, stated qualifications, unresolved professional/public premises, and the actions for which the design can be relied upon.
- **Refusal boundary:** refuse if the submitter lacks the relevant professional assignment; the Intervention or proposed scope is ambiguous; a required premise is materially conflicted; or the submission claims a public authority decision outside professional competence.
- **Deletion consequence:** dispatch/readiness could not distinguish intended scope from professionally certified scope, and public/field actors could be shown an unowned design assertion.
- **Anti-pattern result:** one professional operation over a bounded design, not setters for each scope component.
- **Executive result:** Owen renames and accepts `Certify Technical Intervention Design`. Professional certification never means public/legal authorization.

### A4. Release a public application — **KEEP — ACCEPTED**

- **Decision owner:** beneficiary or authorized representative; a cooperative representative only within the accepted mandate.
- **Bounded semantic inputs:** the exact application Public Proceeding, applicant/beneficiary, released requested scope, required certifications/assertions, representative authority, and the release point required by the governing route.
- **Atomic effects:** releases the identified filing into the public process and freezes the released proceeding scope/basis as required by that operation. It does not determine admissibility, ranking, concession, permit outcome, or payment entitlement.
- **Output:** a released application occurrence and the exact scope now before the public authority, with any next clock or repair owner.
- **Refusal boundary:** refuse if the releasing actor lacks authority; the application Proceeding or requested scope is not identified; a required member/professional certification is absent; or named-action readiness reports an uncured blocking premise.
- **Deletion consequence:** CORDON could prepare a cited case but could not preserve the beneficiary’s reserved act of releasing it, collapsing preparation into submission.
- **Anti-pattern result:** not a generic `submit proceeding` Action: application release and payment-claim release have different governing rights, gates, consequences, and downstream bodies, so they remain separate despite superficial form similarity.
- **Executive result:** Owen accepts one applicant-owned Action for non-payment public applications. Funding, permit, environmental, water and similar application kinds share the contract only where owner/effects remain uniform. Generic filing release is rejected.

### A5. Commit or rebalance Intervention capacity — **KEEP — ACCEPTED**

- **Decision owner:** authorized cooperative role under approved allocation policy and override governance.
- **Bounded semantic inputs:** the set of affected Interventions, current feasible recommendation and alternatives, proposed additions/retentions/releases/reallocations, exact scarce capacities and periods, protected prior firm commitments, policy basis, and any override reason.
- **Atomic effects:** atomically creates, retains, releases, or reallocates the affected F6 capacity commitments so the portfolio remains internally coherent. It does not rewrite public eligibility, concession, duty, creditor identity, member fallback, technical authorization, or physical Intervention scope.
- **Output:** the committed portfolio, binding capacity commitments, deferred Interventions, preserved fallback, and recorded reason where the authorized owner departs from the recommendation.
- **Refusal boundary:** refuse if the submitter lacks allocation authority; the proposal violates a non-discretionary legal/safety/instrument condition, approved fairness safeguard, protected firm commitment, or resource feasibility; an affected Intervention lacks named-action readiness for commitment; or an override lacks the required reason/review basis.
- **Deletion consequence:** CORDON would remain a recommender with no governed way for the cooperative to exercise its separate capacity decision right, and recommendations could be mistaken for commitments.
- **Anti-pattern result:** one portfolio governance transaction rather than `reserve`, `firm`, `schedule`, `release`, and `reallocate` status setters. A later rebalance is the same real portfolio operation over a changed bounded set, not a second generic workflow Action.
- **Executive result:** Owen accepts one atomic Action across the complete affected Intervention set. The portfolio remains derived; the Action writes exact Intervention Capacity Commitment facts. Recommendation never creates a commitment.

### A6. Dispatch Intervention — **KEEP — ACCEPTED**

- **Decision owner:** responsible cooperative, member, or public field manager with actual dispatch authority for the route.
- **Bounded semantic inputs:** one Intervention, the dispatchable authorized scope, assigned executor, scheduled capacity/material commitments, access and permit decisions, active clocks, and the exact execution route.
- **Atomic effects:** authorizes the executor to commence the named field operation within the bounded scope and commits the dispatch consequence. It does not perform the work, certify compliance, accept completion, or alter unrelated route lines.
- **Output:** dispatch authority, executable scope, executor handoff, controlling clock, and preserved blockers for excluded work.
- **Refusal boundary:** refuse if the submitter lacks dispatch authority; named-action readiness is false or materially indeterminate; required authority, target, access, design, permit, site-specific route, materials, lawful water, capacity, finance, clock compatibility, or acceptance evidence plan is missing; or an unresolved conflict can change this dispatch.
- **Deletion consequence:** readiness would have no governed transition into real execution and preparation could again be confused with authorization to enter the field.
- **Anti-pattern result:** real dispatch, not `dispatchStatus=ready` and not an Action that merely calls the readiness Function.
- **Executive result:** Owen accepts one bounded Action across routes while owner class and core effects remain uniform. A real work-order Instrument is created/activated only where the external process preserves one. Route-specific authority/effect differences require selective splitting.

### A7. Attest Intervention performance — **KEEP — ACCEPTED**

- **Decision owner:** authorized executor for its own performance; required beneficiary or technician assertions remain separately attributable.
- **Bounded semantic inputs:** dispatched Intervention scope, actual Parcel/Plant/material/Lot work performed, quantities, exceptions, substitutions, custody handoffs, contemporaneous proof, and executor identity.
- **Atomic effects:** records the executor’s bounded performance assertion and establishes the independently preserved as-built F5 scope and any resulting F9 handoff facts. It does not confer official, public-control, private contractual, or biological acceptance.
- **Output:** attributable as-built result, deviations/residual scope, evidence basis, and the exact acceptance owner now required.
- **Refusal boundary:** refuse if the submitter is not assigned to the claimed work; the claimed work falls outside dispatched authority without an approved change; Lot/material identity or required proof is missing; or the Action attempts to self-accept performance.
- **Deletion consequence:** the system could show intended/authorized work but could not distinguish what the executor says was actually done before independent acceptance.
- **Anti-pattern result:** one execution attestation bundles the cohesive as-built consequence; it is not one Action per quantity, exception, or evidence item.
- **Executive result:** Owen accepts one executor-owned Action across removal, treatment, preparation, planting, rework, replacement and cure while the semantic contract remains uniform. Every submission creates a concrete Field Execution Occurrence for independent review.

### A8. Decide route-specific Intervention acceptance — **REJECTED AND SPLIT**

- **Decision owner:** the exact actor assigned by the controlling route: official inspector/authority for compulsory legal completion; assigned public control body for funded execution; or contract/protocol-assigned party/professional for private acceptance, defects, warranty, and aftercare.
- **Bounded semantic inputs:** one Intervention, the exact acceptance capacity being exercised, as-built scope and evidence, controlling Instrument/Proceeding, accepted/rejected quantities or scope, defects/residual duty, and acceptance authority assignment.
- **Atomic effects:** records one qualified acceptance decision and its bounded consequences for the Intervention, F5 accepted/as-built distinctions where independently preserved, relevant Proceeding scope, and any cure/rework obligation. It never converts one route’s acceptance into another’s.
- **Output:** acceptance kind and owner, accepted and excluded scope, residual duty/defect/cure, and downstream payment or aftercare consequences.
- **Refusal boundary:** refuse if the submitter lacks the exact route-specific acceptance power; the acceptance kind is unspecified; required performance evidence is missing; unresolved conflict can change the decision; or the submission purports to establish cash settlement or biological establishment.
- **Deletion consequence:** CORDON could record execution but not preserve who had power to accept which consequence, violating Questions 5–6 and the accepted separation among executor assertion, legal completion, funded-work control, and private acceptance.
- **Anti-pattern result:** Owen rejects the broad Action because acceptance kind changes decision owner, governing Instrument, evidence, refusal conditions, effects, downstream Proceeding/right and security meaning. It is replaced by A8a–A8c.

### A8a. Decide compulsory compliance acceptance — **KEEP — ACCEPTED**

- **Decision owner:** competent plant-health authority or legally assigned compulsory-route acceptor.
- **Bounded contract:** decide legal completion for inspected compulsory scope against the official duty/order; preserve residual duty, enforcement, sanction, re-entry or remedy consequences.
- **Refusal boundary:** refuse without exact compulsory acceptance authority, official duty/scope, required inspection basis or resolved proposition-specific conflicts. Never decide public-funding or private-contractual acceptance.

### A8b. Decide funded-work acceptance — **KEEP — ACCEPTED**

- **Decision owner:** assigned public control body or competent funding authority.
- **Bounded contract:** decide the executed scope, quantity and evidence accepted for the funded route; enable or limit claim progression and preserve exclusions/cure.
- **Refusal boundary:** refuse without exact public-control authority, concession/right, programme control basis, inspected funded scope or required evidence. Never establish compulsory legal completion or private warranty acceptance.

### A8c. Decide contractual acceptance — **KEEP — ACCEPTED**

- **Decision owner:** contract/protocol-assigned private acceptor or professional.
- **Bounded contract:** decide contractual performance against agreed scope and as-built work; create defect, cure, rework, warranty or aftercare consequences.
- **Refusal boundary:** refuse without exact contractual acceptance authority, operative agreement, inspected work and required proof. Never bind public funding or compulsory plant-health authority.

### A9. Release a payment claim — **KEEP — ACCEPTED**

- **Decision owner:** beneficiary or authorized representative.
- **Bounded semantic inputs:** the exact payment-claim Public Proceeding, underlying entitlement/right, permitted claim stage, claimed scope and amount, admissible spend/evidence, beneficiary identity, and representative authority.
- **Atomic effects:** releases the claim at a stage allowed by the governing right and fixes the claimed proceeding scope. It does not liquidate, order, settle, revoke, or recover payment and does not change creditor identity.
- **Output:** released claim, claimed amount/scope/stage, public review handoff, and active clock or repair owner.
- **Refusal boundary:** refuse if the actor lacks release authority; no applicable entitlement permits the claimed stage; the claim exceeds the surviving right or duplicates incompatible same-operation funding; required evidence/guarantee is absent; or named-action readiness is false.
- **Deletion consequence:** finance could engineer admissible spend, but beneficiary release would be collapsed into preparation or public review and the reserved payment decision right would disappear.
- **Anti-pattern result:** distinct from application release because claim-stage entitlement, evidence, amount, creditor, and settlement consequences are materially different.
- **Executive result:** Owen accepts one beneficiary-owned Action across Instrument-permitted advance, interim, final and other claim stages. It creates filing/claimed-scope facts and never performs public accounting or proves settlement.

### A10. Correct authoritative member or land facts — **CONDITIONAL**

- **Decision owner:** member together with CAA or the authority that owns the authoritative record, according to the record.
- **Bounded semantic inputs:** exact disputed authoritative fact, affected Holding/Parcel/actor, correction basis, competent correcting actor, and the external record/proceeding in which correction legally occurs.
- **Atomic effects:** only the authoritative correction and resulting relationship fact; downstream impact is calculated separately.
- **Output:** corrected authoritative premise or an explicit unresolved conflict and owner.
- **Refusal boundary:** refuse if CORDON is not the authoritative transaction boundary, the correcting actor lacks competence, or evidence cannot resolve the proposition.
- **Deletion consequence:** none from the core if the authoritative system remains the place where correction occurs and CORDON consumes the result. If CORDON becomes an authorized correction channel, deletion would force an unsafe informal workaround.
- **Verdict rationale:** conditional on later proof that the real correction operation is legitimately executed through the Ontology. Do not create a proxy Action merely to imitate a CAA/source-system edit.

### A11. Issue a public determination — **CONDITIONAL**

- **Decision owner:** the public authority assigned to the exact determination (eligibility/admissibility/ranking/concession, permit, compulsory duty, funded-work control, liquidation/order, audit/revocation/recovery, and so on).
- **Bounded semantic inputs:** one identified Public Proceeding, exact statutory power, deciding authority assignment, decided scope, basis, and consequence.
- **Atomic effects:** only the specific public determination and resulting F3/F7/F8 facts that follow from it.
- **Output:** a qualified authority outcome with decided scope and consequences.
- **Refusal boundary:** refuse any generic or cross-power use; the concrete Action must identify one decision power and must not let one authority exercise another’s power.
- **Deletion consequence:** none from the core where CORDON consumes authoritative outcomes. If a competent authority actually decides through CORDON, a concrete decision-specific Action is required.
- **Verdict rationale:** the generic candidate is not KEEP. It is a conditional **pattern** that must split into concrete operations when real use through CORDON is proven. One universal `Issue Determination` would be a God Action and Misnomer.

### A12. Review bounded biological establishment — **CONDITIONAL**

- **Decision owner:** party/professional assigned by the governing contract, protocol, or public route for aftercare and survival/defect review.
- **Bounded semantic inputs:** accepted installation scope, assigned aftercare responsibility, review window, supported Plant/Parcel grain, observed survival/defect basis, and cure/replacement threshold.
- **Atomic effects:** records the bounded establishment determination and opens only the required replacement/cure consequence within the surviving Intervention.
- **Output:** established/defective/unresolved scope, required cure or replacement, owner, and remaining Wedge 1 exposure.
- **Refusal boundary:** refuse if reviewer authority, review window, supported identity grain, or required observations are absent; do not infer full productive maturity.
- **Deletion consequence:** the core still preserves the endpoint if outcomes are authoritatively ingested. If the assigned reviewer makes this decision through CORDON, deletion would collapse installation acceptance into biological establishment.
- **Verdict rationale:** conditional until direct evidence establishes the real review operation and actor at sufficient grain. The semantic distinction is mandatory even if no Action is.

### A13. Record cash settlement — **REJECT**

- **Decision owner:** cash movement is established by treasury/bank evidence, not by a cooperative operator’s discretionary decision.
- **Bounded semantic inputs/effects/outputs:** proposed input is payment-order and bank evidence; proposed effect is a `settled` marker; proposed output is settlement status.
- **Refusal boundary:** it would have to refuse without bank/treasury evidence, which reveals that the Action is only a manual status setter over an authoritative outcome.
- **Deletion consequence:** none. Preserve the settlement fact from authoritative evidence and distinguish it from liquidation and payment order.
- **Verdict rationale:** Golden Hammer and Action Sprawl. A later authenticated bank/treasury operation could be represented by its actual integration or a concrete external Action, but `Record settlement` is not a core human decision.

### A14. Reopen affected work / set ready / advance route — **REJECT**

- **Decision owner:** none as a universal operation. A later material fact changes determinate consequences; the actor who owns that fact corrects or decides it.
- **Bounded semantic inputs/effects/outputs:** these proposals take a route/work item and set generic workflow state.
- **Refusal boundary:** no sound universal boundary exists because applicability, readiness, public decision, capacity, acceptance, payment, and biological reopening have different owners and premises.
- **Deletion consequence:** none. The affected-decision Function identifies impact; real actors then take the specific retained Actions or authoritative external operations.
- **Verdict rationale:** generic workflow-management Action, status setter, and God Object companion. There is no accepted generic WorkItem, Route status, or global case state to edit.

## Candidate Functions

A **KEEP** here means that the semantic operation inherently needs live complex logic. It does not preselect Palantir Functions over another later-supported operational mechanism; it establishes what any implementation must compute and what it may not decide.

### F1. Determine affected decisions — **KEEP — ACCEPTED**

- **Decision owner:** CORDON computes and explains impact; the owner of the changed premise corrects/decides that premise; each downstream decision remains with its accepted owner.
- **Bounded semantic inputs:** one material changed fact or qualified outcome; its prior/current value and effective time; linked Instruments, Areas, Proceedings, rights, Interventions, commitments and assignments; active/dormant decision contexts; proposition-specific conflict scope.
- **Logic/effects:** live dependency traversal determines which accepted decisions or named actions can change, why, and which prior conclusion must be reconsidered. It changes no authoritative fact and takes no reserved decision.
- **Output:** affected decisions/actions, reason chain, next decision owner, scoped hold/reopening consequence, and explicit unaffected work.
- **Refusal boundary:** refuse to assert impact where identity, effect, time, or dependency is unresolved; return indeterminate only for the proposition it can change. Never reopen every line merely because one source changed.
- **Deletion consequence:** Question 1 and selective reopening become manual/global; unaffected work cannot be reliably protected from broad reset.
- **Why live Function logic is justified:** the answer is event-relative and must traverse current cross-object effects, scopes, rights and commitments. A stored universal `affected` status would stale after any dependency change. Event detection/reaction mechanics remain Gate 6; this candidate owns only the current impact computation.
- **Executive result:** Owen accepts one read-only Function across all five responsibilities. It returns scoped impact and unaffected work and never edits or reopens work itself.

### F2. Assess named-action readiness — **KEEP — ACCEPTED**

- **Decision owner:** CORDON computes readiness and explains blockers; the actor authorized for the named Action decides whether to take it; premise owners cure their own facts.
- **Bounded semantic inputs:** one named Action, its target Proceeding/Intervention/right/route, current applicable Instrument effects, actor authority, required public/professional decisions, F5/F6/F9 facts, finance/guarantee conditions, compatible clocks, and required later-acceptance evidence.
- **Logic/effects:** evaluates only the action-specific conditions at the current decision time and resolves blockers to their actual owners. It performs no edit and does not certify professional/public premises.
- **Output:** ready / not ready / materially indeterminate for the named Action; satisfied and failed conditions; cure owner; consequence of proceeding or waiting; and scope that may continue.
- **Refusal boundary:** refuse a generic `route ready` answer; refuse to promote protected-site overlap, raw geometry, missing authority, or unresolved conflict into clearance; refuse to imply readiness for any other Action.
- **Deletion consequence:** every retained Action would duplicate cross-object gating or rely on an unsafe global ready state; Questions 2 and 4 would lose their named-action discipline.
- **Why live Function logic is justified:** readiness depends on current links, clocks, commitments and authoritative outcomes and varies by Action. Stable prerequisites may be stored, but the decision-time conjunction and explanation cannot safely be one precomputed route status. Simple final submission checks may still be enforced by Action criteria; this Function supplies the richer operator answer.
- **Executive result:** Owen accepts one semantic Function with action-specific typed profiles and one shared rule owner. Gate 6 may use one Function or typed wrappers; submission criteria still enforce final refusal.

### F3. Compare feasible Intervention portfolios — **KEEP — ACCEPTED**

- **Decision owner:** CORDON recommends under cooperative-approved policy; the authorized cooperative role commits or overrides.
- **Bounded semantic inputs:** complete affected in-scope Intervention population; non-discretionary constraints; approved fairness safeguards and neutral tie-breaker; current named-action readiness; protected commitments; available capacities/periods; expected incremental realized Xylella-loss reduction and uncertainty relative to each member’s current path.
- **Logic/effects:** constructs feasible portfolios/schedules, identifies binding constraints, compares objective results and materially equivalent alternatives, performs sensitivity analysis, and explains inclusion/deferral. It edits nothing and never reserves capacity.
- **Output:** highest-objective feasible recommendation, feasible alternatives, binding resources, uncertainty/sensitivity, materially equivalent set/tie-break application, and consequences of override.
- **Refusal boundary:** refuse recommendation when required constraints/policy are absent, candidate population is nomination-only/incomplete, protected commitments are omitted, evidence cannot support a unique ordering, or an opaque score hides constraints. Return no unique recommendation when the evidence supports only equivalence.
- **Deletion consequence:** Option A’s accepted non-binding recommendation and alternatives cannot be produced; capacity commitment would revert to opaque nomination or ad hoc prioritization.
- **Why live Function logic is justified:** this is combinatorial cross-object operational logic with current resource contention, policy constraints and alternative portfolios. Storing one ranking cannot represent portfolio feasibility, schedule interaction, protected commitments, or sensitivity.
- **Executive result:** Owen accepts one read-only Function over complete Intervention combinations. It optimizes expected incremental realized Xylella-loss reduction under current constraints and never creates commitments or authoritative selection.

### F4. Determine legal applicability — **REJECT AS A FOURTH CORE FUNCTION**

- **Decision owner:** CORDON may compute only where the authority-grounded rule makes the proposition deterministic; competent authority retains any reserved interpretation/decision.
- **Bounded semantic inputs:** exact Governing Instrument and proposition, authoritative Official Area/geography, relevant date, partial-intersection rule, Parcel/subject, more-specific decision, and scoped conflicts.
- **Logic/effects:** determines legal applicability or only the procedural trigger supported by the inputs; no edits unless a later governed operation persists the resulting F3 fact.
- **Output:** applies / does not apply / trigger only / indeterminate, with exact basis and affected proposition.
- **Refusal boundary:** refuse legal promotion from raw overlap, non-authoritative geometry, missing date/rule, unresolved source conflict, or a question reserved to an authority.
- **Deletion consequence:** none as a core Function if determinate applicability is materialized from authoritative facts when they change or calculated by a supported derived mechanism. Deletion becomes harmful only if operators require current ad hoc cross-object evaluation not safely materializable.
- **Verdict rationale:** Owen accepts materialized `Parcel Official Area Applicability` as the semantic owner and rejects a fourth core Function. The accepted Functions consume/explain it. Gate 6 selects recalculation mechanics. Reopen a live Function only if ad hoc evaluation cannot be materialized without correctness/timeliness loss.

### F5. Re-evaluate public opportunity applicability/eligibility population — **REJECT as a core Function**

- **Decision owner:** public rules/authority own eligibility; CORDON evaluates the complete population and explains candidates.
- **Bounded semantic inputs:** full in-scope Holding/member/land population, Programme/Instrument rules, current facts and effective dates.
- **Logic/effects/output:** deterministic complete-population and selective affected recomputation producing candidate applicability/eligibility explanations.
- **Refusal boundary:** never infer from member interest or management nomination and never turn evaluation into public concession.
- **Deletion consequence:** the calculation remains required, but not as a live Function; it can be event-driven and materialized so the complete population is auditable and reusable.
- **Verdict rationale:** Golden Hammer. This is population-scale recomputation of stable/current facts, not inherently fast request-time cross-object logic. Gate 6 may select an automated transformation or another mechanism. A Function becomes conditional only for a bounded live explanation over already evaluated facts.

### F6. Reconcile public accounting and cash settlement — **REJECT**

- **Decision owner:** public bodies own instruction/liquidation/order; treasury or bank evidence establishes settlement.
- **Bounded semantic inputs:** entitlement, claim, admitted amount, liquidation, payment order, bank/treasury evidence, revocation/recovery outcomes.
- **Logic/effects/output:** proposed `settled/open` calculation and residual amount.
- **Refusal boundary:** settlement cannot be asserted without authoritative cash evidence; contradictory evidence remains unresolved.
- **Deletion consequence:** none. Store each authoritative outcome separately and derive simple residual/display values where useful. The important semantic rule is that order is not settlement, not a need for complex live code.
- **Verdict rationale:** deterministic direct reconciliation over stored facts does not meet the Function threshold.

### F7. Calculate remaining entitlement or bounded establishment work — **REJECT as standalone Functions**

- **Decision owner:** entitlement consequences follow governing right/authority outcomes; establishment/cure decisions remain with assigned reviewers and responsible actors.
- **Bounded semantic inputs:** for entitlement, awarded ceiling, admitted claims, settlement/revocation/recovery; for establishment, accepted installation, review outcomes, defects and completed cure/replacement.
- **Logic/effects/output:** residual monetary right or remaining bounded biological work.
- **Refusal boundary:** do not combine financial and biological completion, infer productive maturity, or overwrite unresolved authority outcomes.
- **Deletion consequence:** none. These are deterministic projections of stored facts and can be displayed/precomputed. When deciding readiness for a new claim or cure Action, F2 consumes the same facts under the named action rather than spawning another Function.
- **Verdict rationale:** avoids Function sprawl and a generic completion calculator.

## Candidate Interfaces

Interfaces below describe possible semantic contracts only. They do not select an application, API language, query service, action-on-interface implementation, or Interface Action constraint.

### I1. Decision-Capable Actor — **KEEP**

- **Decision owner:** Ontology/domain governance with Natural Person and Organization owners validating the contract; each concrete role/decision remains contextual.
- **Candidate contract:** a narrow common identity/display shape plus the capability to be the actor endpoint of applicable F1 assignments, F2 actor–Parcel rights, F7 rights, and F9 Lot allocation/custody. It contains no permanent `member`, `authority`, `beneficiary`, `contractor`, or similar role.
- **Concrete implementers:** Natural Person and Organization only, unless later accepted noun evidence proves another type genuinely has the same actor capability. Agricultural Holding is not silently promoted into an actor.
- **Bounded semantic inputs/effects/outputs:** input is a Person-or-Organization reference where a workflow truly accepts either; no Interface instance or domain fact is created; output is polymorphic traversal/query/action input over the same concrete facts.
- **Refusal boundary:** reject any required property/link/action not universal to both types; reject use that hides whether the actor is a person or organization; reject role fields on endpoints; reject reliance on Interface links/actions in a currently unsupported surface.
- **Deletion consequence:** no semantic fact is lost; concrete Person/Organization branches can represent everything. Deletion costs reusable polymorphic workflows and duplicates actor-accepting logic where current support actually permits it.
- **Verdict rationale:** Owen accepts the shared actor capability because several exact relationships and workflows accept either Natural Person or Organization without changing their semantic contract. Concrete actor identity remains visible. Every relationship still splits by actor type if fact shape, lifecycle, authority, Actions or security meaning differs. Interface support gaps require concrete implementation fallbacks later; Interface Action constraints cannot be treated as behavioral enforcement.

### I2. Entitlement Holder / Creditor — **REJECT**

- **Decision owner:** the operative Instrument/public authority establishes each right; Ontology governance would own any abstraction.
- **Candidate contract:** Natural Person, Organization and Agricultural Holding as interchangeable F7 right holders.
- **Bounded semantic inputs/effects/outputs:** would accept a generic holder and expose rights polymorphically; creates no fact itself.
- **Refusal boundary:** Holding administrative identity, legal personhood, assignee/creditor capacity and payment authority are not one universal capability; contextual F7 role cannot become an endpoint type characteristic.
- **Deletion consequence:** none; F7’s object-backed relationship can target its exact accepted holder types and preserve holder kind.
- **Verdict rationale:** shared participation in one relationship is not yet a common object shape/capability. This would disguise a contextual role as type taxonomy.

### I3. Proceeding Subject — **REJECT**

- **Decision owner:** the competent authority/proceeding establishes subject and scope.
- **Candidate contract:** all accepted noun types that may be a Public Proceeding subject.
- **Bounded semantic inputs/effects/outputs:** would accept any subject and expose generic F8 links.
- **Refusal boundary:** Person, Holding, Parcel, Area, Plant, Lot, Programme, Instrument and Intervention share no universal subject properties or actions; exact subject kind changes what scope means.
- **Deletion consequence:** none; explicit qualified F8 predicates and contextual direct links remain.
- **Verdict rationale:** God Object by Interface. Being mentionable in a proceeding is not a proven shared polymorphic capability.

### I4. Intervention Scope Item / Governed Subject — **REJECT**

- **Decision owner:** technician/authority/physical process owns each exact scope fact.
- **Candidate contract:** Parcel, Plant, Cultivar, Lot, organism target and possibly other nouns under one scope/effect abstraction.
- **Bounded semantic inputs/effects/outputs:** would let one generic link/action attach arbitrary subjects to an Intervention or Instrument.
- **Refusal boundary:** physical target, biological specification, material use, legal effect and formal proceeding scope have different predicates, facts and owners.
- **Deletion consequence:** beneficial: the 16 anti-collapse predicates stay explicit.
- **Verdict rationale:** directly violates Gate 4’s atomic predicate contract and recreates generic `Scope`/`Effect` abstractions.

### I5. Acceptable / Completable Route Object — **REJECT**

- **Decision owner:** route-specific authority varies across application, Intervention, payment and aftercare.
- **Candidate contract:** a shared ready/accept/complete capability across Proceedings, Interventions, rights and routes.
- **Bounded semantic inputs/effects/outputs:** would expose generic readiness and completion Actions.
- **Refusal boundary:** there is no generic readiness, acceptance, or completion state; the owner and consequence vary by named action.
- **Deletion consequence:** none; F2 and the qualified Actions preserve named-action semantics.
- **Verdict rationale:** an Interface wrapper around the rejected global workflow state and generic Action family.

## Coverage against the six operator questions

| Accepted question | Minimum retained semantics |
|---|---|
| 1. What changed, and what does it affect? | F1 computes current affected decisions and protects unaffected work. The underlying fact remains owned by its real actor/source. |
| 2. What is now required, allowed or blocked? | F4 applicability calculation is semantically required but only conditionally a Function; F2 supplies action-specific conditions and scoped blockers. |
| 3. Who chooses, who decides and which route continues? | A1, A2 and A5 preserve member, cooperative-mandate and cooperative-capacity decisions separately. External public determinations remain authoritative outcomes unless A11 is concretely enabled. |
| 4. Is the route ready for the named action? | F2 is the single readiness computation; A3, A4, A5, A6 and A9 each retain their own decision owner and refusal boundary. |
| 5. What was done, and who accepted it? | A7 preserves executor attestation; A8 preserves qualified independent acceptance. No generic completion status is introduced. |
| 6. Did the intended result land, and what remains open? | Distinct stored public-accounting, settlement, installation, biological, revocation/recovery and cure facts remain authoritative; A12 is conditional. F1 selectively reopens affected decisions; F6/F7 reject unnecessary settlement/completion Functions. |

## Cross-boundary invariants

1. Compulsory and voluntary routes can coexist but never inherit each other’s authority, evidence, clock or acceptance.
2. Funded and self-funded recovery share physical/readiness semantics; public application, concession, claim and settlement operations activate only where applicable.
3. Eligibility, participation, cooperative mandate, capacity commitment, public concession, execution, acceptance, settlement and establishment remain separate.
4. Every refusal is scoped to the named operation and proposition it can change; unresolved conflict never freezes unaffected work.
5. A recommendation creates no F6 commitment. A commitment creates no public right. A payment order proves no cash. Installation acceptance proves no biological establishment.
6. Intended, professionally certified, legally authorized, as-built and accepted Intervention scope remain distinguishable where the real process preserves them.
7. External authoritative facts do not require a CORDON Action merely to exist in the Ontology.
8. No Action or Function may manufacture a reserved member, professional, cooperative, contractual or public decision.
9. No Action requires a generic Case, Event, Evidence, Status, Task, Queue, WorkItem, Route object or global timeline.
10. No Interface may erase the concrete noun, exact relationship predicate, decision owner, or uneven current platform support.
