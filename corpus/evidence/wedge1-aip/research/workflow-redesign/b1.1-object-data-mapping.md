# B1.1 object–data mapping

Status: BINDING for B1.1 remediation. Approved through Owen's grill (Q1–Q4), 2026-08-24.
Schemas: quoted from `gate-5-reconciled-operator-graph.md` §Minimum object properties. Nothing here adds a stored property the gate did not grant.
Scope: the B1.1 data plane — the four source-backed duty-slice types. The cooperative private layer (Party, Holding, Intervention and their contextual assignments) is **out of B1.1** and is owned by the accepted Q5/D10 composition plus B2/B5. Action-created hidden occurrence types are B3+ and get no data here.

## Grill decisions this document implements

| Q | Decision |
|---|---|
| Q1 | Row provenance is **source reference + as-of only**. Authority is the link to the basis `GoverningInstrument`. Assurance classification lives in the source register and extract manifest, never as row enums. The first-build `source_class`/`derivation_class`/`verification_class` taxonomy is retired from product schemas. |
| Q2 | `OfficialArea` existence and identity come from the **instrument registry**; current geometry from the **scheduled zone sync** (dated versions, diff = change event); act-derived foglio coverage where no named layer exists; mismatches in both directions are surfaced facts. |
| Q3 | `GoverningInstrument` discovery: BURP RSS heartbeat → `/documenti` catalog as primary document-grain discovery (full listing census ~110k rows; byte-fetch scoped by section/topic) → discovered-document records with bytes + hashes → admission gate. `/bollettini` issue manifests = incremental completeness reconciliation. Measure pages = program-specific reconciliation lane, never the completeness boundary. The seven held instruments re-derive through this path and must match known hashes. Four invariants binding: no page-number-only cursoring; two-view reconciliation; heartbeat sync metadata recorded (SLA alarm is B9); raw listing snapshots preserved. |
| Q4 | Every officially sampled tree is an `IndividualPlant`, positive or negative. Result is observation data, never the identity gate. |
| Standing | Full-universe ingestion when marginal cost is sync time: **full-region cadastre (~4.94M parcels), full monumental registry (341,428), full sample layers (all campaign samples incl. negatives), all zone layers**. Clips are presentation only. |
| Standing | Plant→Parcel is **total**, populated by spatial containment (point-in-polygon against the full cadastre), corroborated by registry attributes where present; disagreement flagged for review; residual failures are quarantine-and-verify items. |
| Standing | No branch/merge ceremony. Data lands on `master`. Review gates are process gates. |

## Dataset ↔ object rule

The **backing dataset** is the physical source of truth: it carries the source's own fields (join keys, technical identifiers) plus the curated columns the object maps. The **object** carries exactly the gate-minimum stored properties. Anything the gate lists as *derived* is a traversal or Function output and is never a column on the object — the first build's `regime`-on-parcel column is the canonical example of the drift this rule prevents.

## Source assurance owner

`source_register` is the sole platform-native owner for source admission, coverage and freshness context. It is produced from Data Connection source configuration and raw transactions. It carries source identity/URL, authority family/voice, covered grain, extraction method, retrieval window, raw transaction references, listing/payload coverage, license where stated, and admitted/blocked/degraded state. Product rows carry only source reference + as-of. B9 reads `source_register` for freshness and coverage monitoring.

## 1. CadastralParcel

**Gate stored properties:** qualified cadastral reference · operator title · current Parcel geometry · current scoped Holding associations · current scoped Party tenure/consent/access details.

The last two are cooperative-context facts — they arrive with the private layer (Q5) and via Actions, not from any public source. B1.1 populates the first three.

**Backing dataset `parcels`** (master):

| Column | Maps to | From |
|---|---|---|
| `qualified_cadastral_ref` (PK) | qualified cadastral reference | `COMUNE`/`SEZIONE`(stripped)/`FOGLIO`/`ALLEGATO`/`SVILUPPO`/`NUMERO`; null-`NUMERO` sentinel `#NULL-{OBJECTID}` |
| `title` | operator title | `NOME_COMUNE` + foglio/particella, human-readable |
| `geometry` | current Parcel geometry (`geoshape`, bound in B2) | Esri rings → RFC 7946 GeoJSON, exterior counterclockwise, multipart → MultiPolygon |
| `comune_code`, `nome_comune`, `foglio`, `particella`, `sezione` | — (join/backstage) | source fields, kept for act-annex foglio resolution and joins |
| `source_url`, `retrieved_at` | — (Q1 provenance) | fetch metadata |

**Current path:** AdE Puglia bulk ZIP → immutable regional artifact + province/cadastral-unit manifest → per-unit GML parse → exact source count checks → pass through validated singleton identities + dissolve only duplicate `NATIONALCADASTRALREFERENCE` rows → `parcels_raw`/rejects → curated `parcels` → OSv2 `CadastralParcel`. The 256 packages are cadastral units, not 257 civil municipalities; E885/Manfredonia covers Zapponeta-area cadastral land. B1.1 has no WFS gap-fill and no SIT Parcel history/reconciliation.

**Not stored (gate-derived):** applicable Areas, regime, duties, applicability, Plants — traversals and Function outputs.

## 2. OfficialArea

**Gate stored properties:** qualified Area reference · official title · area kind · current geometry or territorial representation. `areaKind` spans **administrative jurisdictions** (EU, state, region, province, Comune) **and** epidemic operational areas (infected, containment, buffer, additional delimited).

**Backing dataset `official_areas`** (master):

| Column | Maps to | From |
|---|---|---|
| `area_ref` (PK) | qualified Area reference | epidemic areas: instituting instrument + area name (registry-derived, per Q2). Administrative: ISTAT/comune code |
| `title` | official title | instrument text / layer `DESCRIZIONE` / official comune name |
| `area_kind` | area kind | gate enum above |
| `geometry` | current geometry | zone sync layer geometry (dated versions); comune boundaries from Confini Comunali layer (durable, fetch-once-refresh-rarely) |
| `geometry_as_of`, `source_url` | — (Q1) | sync snapshot date, layer/instrument URL |
| `coverage_foglio` | — (backstage) | act-annex Allegato 2 foglio lists where no named layer exists (Valenzano) — resolved against `parcels.foglio` |

**Two origins, one registry (Q2):** existence/identity rows are minted from admitted instruments (an area exists because an act instituted it); the scheduled zone sync attaches/refreshes geometry by coverage + act citation. A legal area with no named layer carries act-derived foglio coverage. A layer with no known instituting act surfaces as a discovery prompt, never a silent area. Both mismatch directions are Q1 change material.

**Path A (geometry):** SIT zone services (pauca L0–L15, fastidiosa L0–L1, multiplex L0–L2) → scheduled external transform → `official_areas_raw` (dated snapshots preserved) → curate (geometry conversion, diff vs prior snapshot → change events) → `official_areas`.
**Path B (existence):** admitted `instruments` → registry transform → area identity rows.
**Path C (administrative):** Confini Comunali (+ province/region) → one-time sync → rows with `area_kind=comune` etc. These are also the spatial frame for containment joins.

## 3. IndividualPlant

**Gate stored properties:** qualified Plant reference · operator title · current Plant location. Identity gate: *stored only when identity is externally preserved* — monumental registry identity and official sample identity both qualify (Q4: result is not the gate).

**Backing dataset `plants`** (master):

| Column | Maps to | From |
|---|---|---|
| `plant_ref` (PK) | qualified Plant reference | registry: `SCHEDAN`; sampled: `ID_CAMPIONE` (namespaced per identity class) |
| `title` | operator title | e.g. "Monumental olive 12345, Crispiano" / "Sampled olive 1964901, Bari" |
| `location` | current Plant location (`geopoint`, bound B2) | source point, outSR=4326 |
| `parcel_ref` (FK, **total**) | link 5: Parcel contains identified Plant | **spatial containment** against full cadastre; `PROPRFG`/`PROPRPTC` as corroboration; disagreement → review flag; residual failure → quarantine-and-verify |
| `identity_class` | — (backstage) | `registry` / `official_sample` |
| observation columns (`sample_date`, `result`, `species`, `symptoms`, `confirmation_doc_url`) | — (observation data, feeds condition/history derivations) | monitoring fields `DATA_CAMPIONE`, `RISULTATO`, `SPECIE`, `SINTOMI`, `DOCUMENTO_CONFERMA` |
| `source_url`, `retrieved_at` | — (Q1) | fetch metadata |

**Path:** full monumental registry (341,428, all comuni, LOCCOM uppercase) + **all** monitoring sample layers of the three services (full campaign incl. negatives — not the positives-only clip) → external transforms → `plants_raw` → curate (identity namespacing, spatial parcel join, dedupe of resampled trees where source identity supports it) → `plants` → OSv2 `IndividualPlant`.

**Not stored:** official condition, legal-target status, phase involvement — derived. A positive does not set a flag on the plant; it is an observation the derivations read.

## 4. GoverningInstrument

**Gate stored properties:** qualified Instrument reference · official title · Instrument kind · operative interval · bounded operative effect · current scoped party/authority details. *"The full legal corpus, clauses, citation graph, OCR and acquisition history remain backstage."*

**Backing dataset `instruments`** (master), fed by the discovery substrate:

| Column | Maps to | From |
|---|---|---|
| `instrument_ref` (PK) | qualified Instrument reference | issuer + act number + year (e.g. `DDS-2-2026-FITO`) from listing metadata |
| `title` | official title | catalog listing title |
| `instrument_kind` | Instrument kind | deterministic from series/section (DDS, DGR, DET, ordinance…) |
| `operative_interval` | operative interval | publication date from listing; end set by supersession events (history, later) |
| `operative_effect` | bounded operative effect | **deliberately minimal in B1.1**: institution/prescription summary from listing metadata only. Deep parsing of obligations/annexes stays behind the human review gate per canon |
| `document_url`, `sha256`, `retrieved_at` | — (Q1 + evidence) | admitted copy |
| `primary_media_reference` | B2 physical media-reference property `primaryDocument` | one admitted canonical PDF in `Governing Instrument Documents`; contains Media Set/View/Item RIDs and `application/pdf` MIME type |

**Backstage resources (not objects):** `discovered_documents` — full `/documenti` listing census; `instrument_bytes` — immutable content-addressed raw PDFs; `instrument_copies` — copy/hash/admission/media reconciliation; `Governing Instrument Documents` — curated Media Set of admitted/fetched PDFs; `bulletin_issues` — `/bollettini` manifests. These are the backstage corpus the gate names.

**Path:** BURP RSS → `/documenti` catalog → `discovered_documents` + immutable `instrument_bytes` → **admission gate** → admitted PDF promoted once to `Governing Instrument Documents` → MediaReference emitted into `instrument_copies`/`instruments` → OSv2 `GoverningInstrument.primaryDocument`. `/bollettini`, measure pages and municipal albi reconcile copies through the same substrate. The seven held instruments must re-derive with matching hashes and media items — nothing hand-placed or re-fetched.

## Links carried by B1.1 data

Of the 32 links, B1.1's data directly populates: **5** (Parcel contains Plant — FK, total, spatial), **9** (Instrument defines/governs Area — the Q2 registry binding), **6** (Area has parent Area — comune→province→region, administrative). Link **13** (Instrument changes Instrument) begins to populate as discovery finds amendment relationships in listing metadata; its history semantics are later. All other links await the private layer, Actions, or B5 breadth.

## What B1.1 explicitly does not do

No object/link/Action/Function creation (B2+). No notional rows (Q5 grill first). No deep act parsing (review-gated). No `source_class`/`derivation_class`/`verification_class` columns anywhere. No positives-only filter. No comune clip on any source. No hand-placed documents.
