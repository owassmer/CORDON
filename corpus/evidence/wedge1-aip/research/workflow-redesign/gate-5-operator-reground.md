## Correction

The prior Gate 5 admission test was too broad:

> A type survives when deleting it erases a decision-relevant domain fact.

That test preserves real facts belonging to authorities, suppliers, banks, inspectors, contracts and scientific processes even when the cooperative manager does not need a separately navigable type to make or execute a CORDON decision. It converted the full operating model into software representation.

The corrected test is:

> A core Ontology element survives only when deleting it prevents the cooperative manager from answering one of the six accepted questions, taking or supervising an authorized CORDON Action, understanding the consequence, or selectively reopening affected work—and when no simpler object, property, direct link, event projection, derived result or backstage evidence can preserve that capability.

Semantic reality remains necessary. Operator decision value is now additionally required.

## Actual user

The primary user is the cooperative or OP operations manager coordinating overlapping work across many members, Holdings, Parcels, Proceedings, Interventions, resources and payment paths.

The manager does not own every domain decision. CORDON must preserve decision boundaries and support the manager in coordinating the actors who do.

The manager’s six recurring questions remain the primary grammar:

1. What changed, and what does it affect?
2. What is now required, allowed or blocked?
3. Who chooses, who decides, and which route continues?
4. Is the route ready for the named action?
5. What was done, and who accepted it?
6. Did the intended result land, and what remains open?

Land, Funding, Applications, Field Work and Payments remain connected responsibilities. They are not modules or Ontology partitions.

## Stronger Gate 5 admission tests

### 1. Operator decision-loss test

Name the exact manager decision or supervisory action lost if the element is removed. A domain fact used only for audit detail, source fidelity or another actor’s internal process does not automatically pass.

### 2. Operator traversal test

The manager must need to navigate, compare, select, explain or act on the element as an independent thing. If the needed answer is a property, direct relationship, derived set, or event detail on an operator-visible object, do not create another type.

### 3. Action-harness test

An Action survives only when CORDON or its bounded AIP harness can legitimately execute, stage or route it for an authorized actor. Public-authority decisions CORDON merely observes are outcomes, not CORDON Actions.

### 4. Fact-once test

Store the fact once at the smallest operator-meaningful owner. Do not create relationship objects merely to reproduce legal, contractual, scientific or evidence granularity already available through the owning object/event and its basis links.

### 5. Complexity budget test

Every added core type must buy a manager capability impossible without it. If two representations support the same operator decision safely, choose the simpler one even if the richer representation is more normalized.

### 6. Selective reopening test

Detailed domain structures can remain backstage or conditional. Promote one only when a real operator workflow proves that its absence causes a concrete decision failure.
